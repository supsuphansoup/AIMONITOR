## 2. 발견하여 수정한 결함

### 2.1 대시보드 시각이 9시간 어긋남 — **치명적, 확인됨**

`TraceEventRead` 가 타임존 표기 없이 `2026-08-28T06:59:14.167901` 형태로 응답했습니다. 브라우저의 `new Date()` 는 오프셋 없는 문자열을 **로컬 시각**으로 해석하므로, KST 사용자에게는 모든 트레이스가 실제보다 9시간 이르게 표시됐습니다.

```
수정 전: "timestamp": "2026-08-28T06:59:14.167901"       → 브라우저: 06:59 KST (오답)
수정 후: "timestamp": "2026-08-28T06:59:14.167901+00:00" → 브라우저: 15:59 KST (정답)
```

### 2.2 클라이언트 타임스탬프의 오프셋이 버려짐 — **데이터 손상, 확인됨**

`timestamp: "2026-08-28T10:00:00+09:00"` 을 보내면 `10:00 UTC` 로 저장됐습니다. 올바른 값은 `01:00 UTC` 입니다. 9시간 미래로 밀린 이벤트가 시계열 버킷에 들어가 그래프를 왜곡했습니다.

수집 시 UTC 로 변환한 뒤 저장하도록 고쳤습니다. 저장은 naive UTC, 응답은 aware UTC — 이 규칙을 `backend/app/core/timeutil.py` 한 곳에 모았습니다.

### 2.3 모르는 모델에 가짜 비용을 붙임 — **신뢰성, 확인됨**

단가표에 없는 모델은 조용히 `$1.00 / $3.00 per 1M` 로 계산됐습니다. 100만 토큰짜리 호출 하나가 **$4.00 이라는 근거 없는 금액**으로 집계됐습니다. 프로젝트 규칙("가격 정보가 없으면 0원이 아니라 `계산 불가`")에도 어긋납니다.

`cost_source` 필드를 도입해 비용의 출처를 명시합니다.

| `cost_source` | 의미 | 표시 |
| :--- | :--- | :--- |
| `pricing_table` | 내장 단가표 기준 | 계산 금액 |
| `custom` | 호출자가 직접 전달 | 전달 금액 |
| `local_free` | 로컬 추론, 과금 없음 | `$0.00000` |
| `unknown` | **단가 없음** | **`계산 불가`** |

집계 API는 `cost_unknown_count` 를 함께 반환하고, 대시보드는 "21건 계산 불가" 처럼 표시합니다.

### 2.4 알림이 사람이 볼 때만 동작 — **기능 공백**

`POST /alerts/evaluate` 를 호출해야만 규칙이 평가됐습니다. 아무도 대시보드를 열지 않으면 **아무것도 감시되지 않았습니다.** 백그라운드 스케줄러를 추가했습니다(기본 60초 주기).

동시에 **쿨다운**을 도입했습니다. 쿨다운이 없으면 60초 주기 스케줄러가 한 번의 장애를 60개의 Webhook 메시지로 바꿉니다. 규칙별 `cooldown_minutes`(기본 15분) 안에서는 재발동하지 않습니다.

### 2.5 집계가 전체 테이블을 메모리로 적재 — **확장성**

`get_overview_metrics` 가 조건에 맞는 **모든 행을 ORM 객체로 만든 뒤** 파이썬에서 합계를 냈습니다. 한 달치 트래픽이 쌓인 테이블에서는 대시보드 폴링 한 번이 프로세스를 정지시킵니다.

- 건수·합계·평균은 SQL 집계(`COUNT`/`SUM`/`AVG`)로 이관
- 모델별 분해는 `GROUP BY` 로 이관
- 백분위수는 `latency_ms` 컬럼만 조회하고 `MAX_AGGREGATION_ROWS`(기본 20만) 로 상한
- 상한에 걸리면 응답에 `latency_sampled: true` 를 실어 **근사치임을 숨기지 않습니다**

### 2.6 그 밖의 수정

| 문제 | 조치 |
| :--- | :--- |
| 오류 응답이 예외 문자열을 그대로 노출 (페이로드 유출 가능) | 서버 로그로만 남기고 일반 메시지 반환, `raise ... from None` |
| 배치 크기 무제한 | `MAX_BATCH_SIZE`(기본 500) 초과 시 422 |
| 규칙 삭제 시 이력이 고아 레코드로 남음 | 이력 선삭제 + SQLite `PRAGMA foreign_keys=ON` |
| 잘못된 `metric_type` 으로 규칙 생성 가능 | 지표 카탈로그 기반 검증 + `GET /alerts/metrics` 제공 |
| 잘못된 `status` 필터가 빈 결과 반환 | 422 로 명확히 거부 |
| `webhook_url` 스킴 미검증 | `http(s)://` 강제 |
| CORS 가 `*` + credentials 동시 허용 (브라우저가 거부하는 조합) | 와일드카드면 credentials 자동 비활성화 |
| SPA 폴백의 경로 탈출 가능성 | `resolve()` 후 dist 하위 여부 확인 |
| `.animate-spin` CSS 미정의 (새로고침 아이콘이 돌지 않음) | 키프레임 추가 |
| 프론트엔드가 실패를 콘솔에만 기록 | 연결 배너 + 상태 표시등 |
| 시작 로그 오타 `retention=offd` | 수정 |

## 3. 추가한 기능

### 3.1 API 키 인증 (`backend/app/core/security.py`)

- `X-API-Key` 헤더 또는 `Authorization: Bearer` 지원, `hmac.compare_digest` 로 비교
- `API_KEY` 미설정 시 **개방 모드**로 동작하되 시작 시 경고 로그
- `REQUIRE_AUTH_FOR_READS` 로 조회 보호 여부 선택
- `/health` 는 항상 공개 (헬스체크가 키를 요구하면 안 됨)

### 3.2 프롬프트 캐시 단가 분리

`cache_read_tokens` / `cache_write_tokens` 를 별도 필드로 수집합니다. 캐시 쓰기는 할증, 읽기는 할인이므로 일반 입력 단가로 뭉뚱그리면 캐시를 쓰는 모든 호출의 비용이 틀립니다.

Anthropic 기준 100만 토큰:

| 구분 | 단가 | 금액 |
| :--- | :--- | :--- |
| 캐시 읽기 | 입력의 0.10배 | `$0.30` |
| 일반 입력 | 기준 | `$3.00` |
| 캐시 쓰기 | 입력의 1.25배 | `$3.75` |

모델별 명시 단가가 없으면 프로바이더 정책 배수를 적용하며, 모르는 프로바이더는 할인 없이 입력 단가를 그대로 씁니다. 적용 중인 표는 `GET /api/v1/system/pricing` 으로 확인합니다.

### 3.3 원문 미저장 강제 (`backend/app/core/sanitize.py`)

SDK 사용자는 요청 객체를 통째로 메타데이터에 넘기기 쉽습니다. 수집 시점에 `prompt`, `response`, `content`, `message`, `query` 등 **내용성 키를 재귀적으로 `[redacted]` 로 치환**합니다. 메타데이터 크기(기본 8KB), 태그 수(20개), 에러 문자열 길이(2000자)에도 상한을 뒀습니다. 요청 본문은 로그에도 남기지 않습니다.

### 3.4 데이터 보관 정책

`RETENTION_DAYS` 설정 시 스케줄러가 주기적으로 오래된 트레이스와 알림 이력을 삭제합니다. 기본값 `0`(무제한)이므로 기존 배포가 업그레이드만으로 데이터를 잃지 않습니다. 즉시 정리는 `POST /api/v1/system/purge?days=N`.

### 3.5 무중단 스키마 업그레이드 (`ensure_schema`)

`create_all` 은 기존 테이블에 컬럼을 추가하지 않습니다. v0.1.0 DB를 그대로 쓰면 새 컬럼에서 즉시 실패합니다. 모델 메타데이터와 실제 스키마를 비교해 **누락 컬럼만 `ALTER TABLE ADD COLUMN`** 하도록 했습니다. 삭제나 타입 변경은 하지 않으며, 여러 번 실행해도 안전합니다. v0.1.0 스키마를 실제로 만들어 검증하는 테스트가 있습니다(`test_schema_upgrade.py`).

### 3.6 운영 엔드포인트

- `GET /api/v1/system/ready` — DB 확인 포함 readiness (`/health` 는 liveness 유지)
- `GET /api/v1/system/info` — 버전, 인증 여부, 스케줄러 상태, 보관 기간
- `GET /api/v1/system/pricing` — 단가표 전체
- 모든 요청에 `X-Request-ID` 부여 및 접근 로그(메서드/경로/상태/소요시간만)

### 3.7 Python SDK

- **토큰 자동 추출**: 데코레이터가 프로바이더 응답에서 토큰 수를 읽습니다. 기존에는 지연 시간만 기록해 **비용이 항상 0** 이었습니다. OpenAI / Anthropic(캐시 카운터 포함) / Google / dict 형태를 인식하고, 모르는 형태는 0을 반환합니다.
- **백그라운드 전송**: `background=True` 시 큐에 넣고 워커가 배치 전송 — 요청 경로에서 네트워크 대기가 사라집니다. 큐가 차면 블로킹 대신 드롭합니다.
- **API 키**, `cache_*` 필드, `trace_id` 지정 지원
- `pip install -e sdk/python` 로 설치 가능 (`aimonitor-sdk`)

### 3.8 대시보드

- 조회 기간 전환 (1H / 6H / 24H / 7D / 30D)
- 연결 상태 표시등, 실패 시 배너 — **백엔드가 죽은 것과 트래픽이 없는 것을 구분**
- 401 발생 시 API 키 입력 안내 및 저장 (브라우저 로컬)
- 비용 미산정 건 `계산 불가` 표시, 캐시 토큰 KPI
- 규칙 일시 중지/재개, 쿨다운 설정, 지표 목록을 서버에서 조회
- 트레이스 페이지네이션, 탭이 숨겨지면 폴링 중단
- 차트를 지연 로딩해 초기 번들 581KB → **185KB**

### 4.2 실제 동작 확인

로컬 서버에 6시간 분량 트래픽 149건(의도적으로 단가 미등록 모델 포함)을 주입해 브라우저에서 확인했습니다.

- KPI: 총 149건, P95 1.12s, 에러율 5.4%, **"21건 계산 불가"**
- 트레이스 표: 미등록 모델 행에 `계산 불가`, 캐시 사용 행에 `cache 3,629`
- 시각: UTC 저장 이벤트가 KST 로 정확히 표시
- 알림: 두 규칙 모두 발동, 메시지에 단위(`ms`, `%`) 포함, "최근 발동 34초 전"
- 규칙 일시 중지 버튼 → `PATCH` → `Active` → `Paused` 반영
- 인증 서버(`REQUIRE_AUTH_FOR_READS=true`)에서 401 배너 → 키 입력 → 데이터 로드 → 표시등 녹색

## 5. 업그레이드 방법

v0.1.0 에서 올라오는 경우:

```bash
git pull
pip install -r backend/requirements.txt
docker compose up --build -d     # 또는 서버 재시작
```

기존 SQLite 파일은 그대로 두면 됩니다. 시작 시 누락 컬럼이 자동 추가되고 기존 행은 기본값(`cost_source='unknown'`, 캐시 토큰 0)을 갖습니다.

> **기존 데이터의 비용 값은 재계산되지 않습니다.** v0.1.0 이 추정치로 채운 금액은 그대로 남고 `cost_source` 만 `unknown` 이 됩니다. 정확한 과거 비용이 필요하면 해당 구간을 재수집하세요.

**외부에 노출하기 전 반드시 `API_KEY` 를 설정하세요.** 미설정 시 시작 로그에 경고가 남습니다.

## 6. 남은 과제

이번 범위에 넣지 않은 항목입니다.

| 항목 | 사유 |
| :--- | :--- |
| PostgreSQL 지원 | 코드는 dialect 중립이지만 검증은 SQLite 로만 했습니다 |
| 사용자별 계정·권한 | 단일 공유 키 모델입니다. 다중 테넌트에는 부족합니다 |
| 요청 속도 제한 | 리버스 프록시 계층에 두는 편이 적절하다고 판단했습니다 |
| WebSocket 실시간 푸시 | 현재는 5초 폴링입니다 |
| 알림 채널 확장 (이메일, PagerDuty) | Webhook 만 지원합니다 |

### 문서 정합성 문제

저장소 최상위의 `PRD.md` / `PLAN.md` 는 **다른 제품**(K-LLM Monitor — Windows 트레이 기반 Claude Code 사용량 모니터)의 명세이며, 실제 구현된 AIMONITOR 와 무관합니다. AIMONITOR 의 명세는 `docs/PRD.md` 입니다. `CLAUDE.md` 의 "아직 코드가 없는 저장소다" 라는 서술도 현재 상태와 맞지 않습니다.

이번 작업에서는 **문서를 삭제하지 않았습니다** — 다른 프로젝트의 산출물일 수 있어 판단을 넘깁니다. 다만 `CLAUDE.md` 에 명시된 규칙 중 이 제품에 적용 가능한 세 가지는 이번 릴리스에서 코드로 구현했습니다.

1. 가격 정보가 없으면 0원이 아니라 `계산 불가` → `cost_source='unknown'`
2. 캐시 읽기와 쓰기의 단가를 합산하지 않음 → `cache_read_tokens` / `cache_write_tokens` 분리
3. 프롬프트·응답 원문을 DB·로그·오류 기록 어디에도 남기지 않음 → `sanitize.py`, 오류 응답 일반화
